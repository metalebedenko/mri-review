# Миллиметры, разметки и сопоставимость

## Единое определение показателя

До разметки назвать объект, область/сторону, плоскость, фазу, ориентиры и вид величины. Раздельно хранить длинный/короткий диаметр, толщину, длину по выбранному направлению, расстояние до опорной линии и проекцию на ось пациента. Выбранные линии не образуют автоматически три согласованные оси объёма; один срез не гарантирует максимума объекта. Конкретное определение выбирается по анатомическому профилю.

Для нового исследования повторять определение показателя и анатомический ориентир, не абсолютные координаты старых пикселей. Если прежний объект или его граница не выделяются, указать `неизмеримо`/`не выделено` с причиной; не подставлять 0 мм. Новый показатель или другая база отсчёта получают отдельную метку, без тихого замещения старого.

## Геометрия исходного кадра

Сохранять `[column, row]` от нуля по центрам пикселей; дробные значения выражают выбор между центрами. Это не соглашение [DICOM SCOORD](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.18.6.html) с отсчётом от края пикселя. Для того же кадра и сетки центр первого пикселя SCOORD `(0.5,0.5)` соответствует здесь `(0,0)`: из обеих координат вычитается `0.5`. При импорте также проверить исходный кадр, frame/total-pixel-matrix origin и преобразования изображения; одно вычитание не исправляет другой кадр, обрезку или поворот.

Для точки `p = (c, r)`:

```text
X(p) = IPP + c × PixelSpacing[1] × IOP[0:3]
           + r × PixelSpacing[0] × IOP[3:6]
```

Здесь IPP — центр пикселя `[0,0]`, PixelSpacing задан как `[row_mm, column_mm]`. Проверить единичность/ортогональность векторов IOP и положительный масштаб. Геометрия берётся из конкретного файла/кадра. Основание: [DICOM Image Plane Module](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.7.6.2.html).

Вычислять в физических координатах:

- `length`: евклидова длина отрезка между двумя точками.
- `perpendicular`: расстояние точки P до бесконечной прямой C0–C1, `|cross(P−C0, C1−C0)| / |C1−C0|`. Сохранять параметр проекции; если основание лежит за концами отрезка, явно показывать продолжение опорной линии.
- `patient_axis_projection`: абсолютная проекция разности двух точек на явно заданную единичную ось; например, `[0,0,1]` для оси Z. Не называть это полной длиной объекта.

Не измерять линейкой по изменённому PNG/скриншоту. Если точки выбраны на увеличенном/обрезанном/повёрнутом превью, сохранить и проверить обратное преобразование в исходную сетку. Масштабная линейка корректна только для текущего преобразования изображения.

PixelSpacing задаёт масштаб сохранённой сетки. AcquisitionMatrix описывает приобретённые данные до реконструкции; интерполяция не создаёт нового анатомического разрешения. Корректный DICOM-размер не делить повторно на коэффициент реконструкции. См. [MR Image Module](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.8.3.html).

## Минимальный реестр измерения

| Поле | Что хранить |
|---|---|
| Идентичность | Постоянные ID исследования и измерения, дата, область/структура, сторона, фаза при применимости |
| Источник | Относительный путь, SHA-256, Study/Series/SOP UID; для multi-frame номер кадра и его геометрия; серия/номер изображения для удобства |
| Геометрия | Rows/Columns, PixelSpacing, IPP, IOP, толщина/фактический шаг и тип источника: native или derived |
| Определение | Вид расстояния, точные точки исходной сетки, ориентиры, ось проекции, правила контура |
| Результат | Неокруглённые мм, отображаемые мм, уверенность в ориентирах и ограничения |
| Контроль | Ссылка на калипер, версия кода/метода, дата, проверка арифметики и связь с прежней метрикой |

Исходники и реестр с данными пациента остаются в его закрытом проекте. Для публичных примеров использовать только синтетические записи; удаление имени или полного UID не гарантирует обезличивание. Округлять для отчёта соразмерно данным, не теряя исходного значения. Дельты считать до округления.

## Калькулятор

[measure_landmarks.py](../scripts/measure_landmarks.py) использует только стандартную библиотеку Python. Он проверяет числовую геометрию и рассчитывает уже выбранные точки; не читает DICOM, не сегментирует ткани и не подтверждает анатомический выбор или подлинность метаданных. Формат — JSON с `coordinate_convention: "zero_based_pixel_centers"` и списком `measurements`.

Результат содержит всю переданную запись в поле `input_record`, включая дополнительные поля. Идентификаторы, даты, пути и заметки из входа могут попасть в выходной JSON. Калькулятор не является средством обезличивания; реальные входы и результаты не публиковать.

[synthetic-landmarks.json](synthetic-landmarks.json) — искусственные данные для проверки запуска, без сведений пациента. Команда из корня репозитория:

```sh
python3 scripts/measure_landmarks.py references/synthetic-landmarks.json
```

Для записи результата добавить `--output result.json`. Существующий файл не перезаписывается. Поля записи: `id`, `kind`, `pixel_spacing_mm`, `ipp_mm`, `iop`; для перпендикуляра — `line` из двух точек и `point`; для остальных — `points` из двух точек, для проекции дополнительно `axis` из трёх чисел. Геометрию сначала сверить с исходным DICOM/кадром. Старый реестр можно адаптировать в отдельный входной файл, сохранив оригинал.

Поля `rows` и `columns` необязательны, но задаются вместе. Без них калькулятор не проверяет верхнюю границу координат. При их наличии допустимы точки между центрами крайних пикселей: `0 ≤ column ≤ columns − 1`, `0 ≤ row ≤ rows − 1`. Это более узкая область, чем вся площадь пикселей в SCOORD; координаты у внешнего края могут быть неподдерживаемыми. Числовые допуски проверки ортогональности и длины опорной линии относятся к реализации, а не к клинической точности или нормам DICOM. Успешный расчёт не подтверждает точность выбора границы.

## Ограничения сравнения и MPR

Сопоставимые числа требуют одинакового смысла метрики, близкой плоскости и анатомических ориентиров. Одинаковая формула при разных частях объекта даёт изменение выбранной метрики, не доказанную регрессию максимального размера. Официальный размер и собственный калипер не взаимозаменяемы без знания метода врача.

При малой разнице полезен контроль выбора соседних срезов и чувствительности ручных точек. Если применять вычислительные смещения, использовать одинаковый физический радиус в мм для обоих исследований, а не одинаковое число пикселей. Радиус обосновывать видимостью конкретной границы; универсальная погрешность в миллиметрах не установлена. Экстремумы такого испытания не являются доверительным интервалом и могут включать анатомически невозможные точки.

В 3D/MPR сохранять исходные UID/кадры, физический affine, плоскость, интерполяцию, маску покрытия и размер исходного вокселя. Проверить соответствие исходных центров вокселей и преобразований. Более мелкий выходной растр не повышает исходное разрешение. Усреднение слоя не воспроизводит автоматически профиль 2D МР-среза. Локальное жёсткое сопоставление по ориентирам не выдавать за валидированную регистрацию; системы координат разных исследований сами по себе не совмещены.

Не вычислять объём как эллипсоид из несогласованных осей, процент функционального восстановления из линейного размера или процент уменьшения при отсутствующей исходной/последующей величине. Расчёт может быть точным при неопределённой анатомической границе — эти уровни уверенности хранить отдельно.

## Предел линейного помощника

Все точки одной записи `measure_landmarks.py` относятся к одной исходной сетке и одному кадру с заданными IPP/IOP. Для точек из разных кадров, 3D-масок, изогнутой длины, площади или объёма нужен другой проверенный расчёт с геометрией каждого источника. Не помещать точки разных кадров в одну запись, оставив геометрию одного из них.

Для ADC, перфузии, потока, долей, карт релаксации и других величин нужны соответствующие единицы и калибровка, а не поле `value_mm`; читать [specialized-mri.md](specialized-mri.md). Сам факт наличия числа в DICOM не доказывает сопоставимость с другой картой/протоколом.
