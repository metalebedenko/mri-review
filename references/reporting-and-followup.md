# Отчёт, сохранение и следующий запуск

## Отчёт соответствует наличию данных

Первым абзацем назвать доступные материалы и реально выполненный объём. Обозначить исследовательский характер результата и отсутствие клинической валидации скилла; наблюдения ИИ требуют проверки квалифицированным специалистом. Структуру сокращать до применимых разделов, сохраняя краткий перечень ограничений. Один МРТ не требует пустой сравнительной таблицы, отсутствие анамнеза — выдуманного клинического заключения. Не обозначать недоступный модуль выполненным.

Базовое ядро: технические характеристики/покрытие; описание и исследовательское заключение каждого доступного исследования; реестр находок и измерений с источниками; уверенность и нерешённые вопросы; понятное резюме. Для текстового режима ядро — точный разбор врачебного описания, без собственных визуальных находок.

Условные разделы:

- При нескольких МРТ: сопоставимость, все охваченные структуры по профилю, отдельный разбор значимых находок и отношений, динамика с уверенностью.
- При протоколах: сверка для каждого имеющегося документа и объяснение поправок.
- При анамнезе: анатомическое соответствие, альтернативы, хронология, влияние терапии на интерпретацию, вопросы врачу. При неполных данных — точные границы вывода.
- Для передачи другому ИИ: самостоятельное резюме фактов, чисел, источников и ограничений, не требующее читать переписку.

В полном случае эти блоки образуют десять частей: техника; отдельное A; отдельное B; сравнение по структурам/объектам; углублённый разбор значимых находок; сверка; клиника; альтернативы/неопределённости; вопросы врачу; передача другому ИИ. Это пример полного объёма, не обязательная форма для одного МРТ.

Маркировать происхождение утверждений: изображения, официальный текст, сообщение пациента, документ осмотра, расчёт, исследовательская интерпретация. Врачебные числа сохранять с «до», диапазонами и исходными единицами; преобразование см→мм фиксировать. Не выдавать отсутствие новой находки за доказанную норму, а вычислительные пределы — за статистическую точность.

## Доказательства и версии

Удобная структура внутри существующего проекта, без обязательного переименования старых каталогов:

```text
analysis/
  status.json                       доступность материалов и состояние модулей
  studies/<stable-study-id>/         инвентарь, просмотр, находки, разметки, отчёт
  comparisons/<pair-or-timeline>/    соответствия плоскостей, метрики, динамика
  official_review/                  только когда предоставлены протоколы
  clinical/                         только когда предоставлен анамнез
  final/                            актуальный итог и структурированные данные
  archive/                          сохранённые заменённые версии
```

Не создавать пустые папки под отсутствующие модули. Минимальные состояния: `pending`, `complete`, `not_available`, `not_applicable`, `limited`; рядом причина, реально просмотренные источники и дата. Указать отдельно полноту выполнения разрешённого объёма и полноту медицинских данных.

Для завершённых этапов сохранять неизменяемую исходную версию, SHA-256 и текст. Дополнение не скрывает первоначальную ошибку: содержит старую/новую формулировку, основание, новые источники и уверенность. После позднего анамнеза не заменять исходное описание снимков. Снимок старого status внутри машинной передачи обозначить историческим; текущий статус держать отдельно.

Итоговый JSON содержит область/вопрос, выбранный анатомический профиль и его источники, список исследований/источников, доступность модулей, определения и полные записи измерений, имеющиеся пары, официальный и клинический контекст с происхождением, исправления и ограничения. Отсутствующие значения — `null` с причиной либо явно отсутствующий модуль, а не 0 и не нормальная находка.

## Проверки перед выдачей

- Значения в отчёте и JSON совпадают с реестром; расчёты воспроизводятся по исходной геометрии, источники/хеши проверены, изменения считаются до округления.
- Каждая ключевая иллюстрация имеет правильную сторону, серию/кадр, подпись и масштаб. На derived-изображении виден статус производного материала.
- Документ согласован сам с собой: первоначальные выводы и последующие поправки различимы; врачебные и собственные размеры не смешаны; пробелы в данных явно отмечены.
- Для DOCX/PDF все страницы отрендерены и визуально проверены. Предпочтительный авторитетный renderer использовать при доступности; fallback назвать. Не выдавать успешное создание файла за проверку вёрстки.
- Итоговый файл открывается; сохранены источники и воспроизводимая передача. Отдельную папку копий создавать по запросу, проверяя совпадение SHA-256; копия не становится вторым редактируемым каноном.

## Когда появляется новое МРТ или другой материал

1. Прочитать актуальное состояние и ограничения, проверить исходный реестр и хеши. Не повторять выполненный анализ автоматически.
2. Добавить новое исследование с постоянным ID, не превращая старое B в A путём перезаписи. Повторить технический допуск и отдельное описание; степень предварительного знания обозначить.
3. При разрешённом сравнении повторить определения прежних метрик. Старые номера срезов и координаты служат адресом прошлого, не шаблоном точек нового изображения. Если метрика больше не воспроизводима, назвать причину и при необходимости ввести новую.
4. Выбрать необходимые пары либо временной ряд; различать изменившиеся протоколы и изменения анатомии. Не выводить скорость изменения из двух неполностью сопоставимых точек без основания.
5. Позднее заключение подключить только к сверке, поздний анамнез — к клиническому модулю. Сохранить прежние выводы и показать, какие выводы изменились и почему.
6. Обновить актуальный итог и состояние. До появления новых данных предыдущий доступный объём остаётся завершённым; отсутствие необязательных материалов не превращает его в бесконечно заблокированную задачу.

При изменении области, вопроса, типа МРТ или группы пациента заново проверить применимость [анатомического профиля](anatomy-profiles.md) и критериев. Сам общий процесс сохраняется. Для динамических/количественных результатов также фиксировать фазу, единицы, калибровку и метод обработки; не сводить их к таблице линейных размеров.
